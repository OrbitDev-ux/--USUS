# Syntax Studio Services Bot

개발 외주 회사를 위한 **올인원 Discord 운영 플랫폼**입니다.
외주 상담·견적·주문·프로젝트 관리부터 커뮤니티 관리(인증·티켓·공지·로그·제재)까지 디스코드 하나에서 처리합니다.

## 기술 스택

- TypeScript (strict, `any` 금지)
- discord.js v14 / Node.js 20+ / pnpm
- 데이터 저장: **JSON** (`data/` 폴더, 원자적 쓰기 + 손상 자동 복구)

## 시작하기

```bash
pnpm install
cp .env.example .env   # 토큰·클라이언트 ID 입력
pnpm deploy-commands   # 슬래시 명령어 등록
pnpm dev               # 개발 모드 (tsx watch)
```

프로덕션: `pnpm build && pnpm start`

### 필요한 봇 권한/인텐트

- 인텐트: Guilds, Guild Members, Guild Messages, Message Content, Guild Moderation
- 권한: 채널 관리, 역할 관리, 멤버 차단, 메시지 보내기, 임베드 링크
- `.서버초기화`/`.서버백업`이 모든 역할을 삭제·생성하려면 봇 역할이 서버 내 다른 역할보다 위에 있어야 합니다. 봇보다 높은 역할은 삭제되지 않고 건너뜁니다.

## 사용 방법

일반 사용자는 슬래시 명령어를 쓰지 않습니다. **패널의 버튼·모달**과 접두사 명령어(`.`)로 이용합니다.

### 일반 명령어 (누구나 사용 가능, 접두사 `.`)

| 명령어 | 설명 |
|---|---|
| `.핑` | 봇의 응답 속도(왕복 지연·웹소켓 핑) 확인 |
| `.도움말` | 일반/관리자 명령어와 패널 이용 방법 안내 |
| `.미니게임` | 드롭다운 메뉴로 가위바위보·주사위·숫자맞추기(1~100, 7회 이내) 선택 후 플레이 |

### 관리자 접두사 명령어 (서버 관리 권한 필요, 접두사 `.`)

| 명령어 | 설명 |
|---|---|
| `.채널생성` | 버튼 → 모달(이름·개수·종류)로 채널을 최대 20개까지 한 번에 병렬 생성. 개수 1이면 이름 그대로, 2 이상이면 `이름-1`, `이름-2`… 형식 |

### 서버 관리 명령어 (⚠️ Administrator 권한 필요, 접두사 `.`)

| 명령어 | 설명 |
|---|---|
| `.서버저장` | 현재 서버의 채널·역할 구조를 백업(`data/server-backups.json`)으로 저장 |
| `.서버초기화` | 모든 채널·역할 삭제. 실행 즉시 자동으로 `.서버저장`을 수행한 뒤, 30초 안에 버튼으로 재확인해야 진행됨 |
| `.서버백업` | 저장된 백업으로 채널·역할 구조를 복구. 마찬가지로 30초 안에 버튼 재확인 필요 |

**되돌릴 수 없는 작업**이며 `/경고`·`/차단` 등과 달리 서버 관리(`ManageGuild`)가 아닌 **Administrator 권한**을 요구합니다. 백업은 채널·역할의 이름·권한·카테고리 배치·순서만 복원하며, 메시지 기록·정확한 채널/역할 ID·웹훅·연동은 복구되지 않습니다(디스코드 API 자체의 한계).

### 관리자 명령어 (서버 관리 권한 필요)

| 명령어 | 설명 |
|---|---|
| `/setup 인증패널·티켓패널·견적패널` | 각 패널을 채널에 설치 |
| `/설정` | 채널·역할·기능·메시지를 GUI(셀렉트/버튼/모달)로 설정 |
| `/공지` | 모달로 작성하는 임베드 공지 (제목·내용·이미지·색상) |
| `/업데이트` | 버전 입력 후 모달(추가·수정·개선·삭제·예정)로 릴리즈 노트 게시 |
| `/점검 예정·긴급·완료·연장` | 점검 안내 게시 (완료·연장은 진행 중인 점검이 있어야 가능) |
| `/경고 지급·목록·초기화` | 경고 관리 (DM 통지 + 로그) |
| `/타임아웃 부여·해제` | 타임아웃 관리 |
| `/킥` | 멤버 추방 |
| `/차단 추가·해제` | 차단 관리 |
| `/주문 목록·상태·진행률` | 외주 주문 관리 (상태 변경 시 주문 채널에 자동 통지, 완료 시 후기 작성 버튼 첨부) |
| `/포트폴리오 추가·목록·삭제` | 포트폴리오 등록·게시 |
| `/통계` | 멤버·티켓·경고·신고·후기·주문 현황 집계 |
| **🚨 신고하기** (유저 우클릭 → 앱) | 유저 대상 신고 모달 → 직원에게 처리/반려 버튼과 함께 통지 |

### 사용자 흐름

- **인증**: 인증 패널 버튼 → 인증 역할 자동 부여
- **티켓**: 티켓 패널 버튼 → 모달 작성 → 비공개 티켓 채널 생성 → 종료/삭제 버튼
- **외주 견적**: 견적 패널 버튼 → 견적 요청 모달(서비스·예산·마감일·상세) → 비공개 주문 채널 생성 + 직원 호출 → 진행률 바로 상태 공유
- **신고**: 대상 유저 우클릭(모바일: 길게 누르기) → 앱 → 🚨 신고하기 → 사유 모달 → 신고 접수 채널에 처리/반려 버튼과 함께 게시
- **후기**: 주문이 완료(`/주문 상태` → 완료) 처리되면 주문 채널에 후기 작성 버튼이 함께 게시되고, 의뢰인이 별점(1~5)·내용을 남기면 후기 채널에 자동 게시 (주문당 1회만 가능)

### 자동 기능

- 환영/퇴장 메시지 (`{user}` `{server}` `{memberCount}` 템플릿)
- 로그: 입장·퇴장·인증·티켓·공지·주문·제재·메시지 수정/삭제
- **오토모드** (`/설정` → 오토모드 ON/OFF, 규칙별 개별 토글): 욕설·도배·반복 메시지·링크·초대 링크·멘션 도배·대량 이모지·대량 대문자 감지 시 메시지 자동 삭제 + 경고 자동 지급 + 로그 기록. 직원/관리자는 예외.

## 프로젝트 구조

```
src/
  commands/     관리자 슬래시 명령어
  components/   버튼·모달·셀렉트 핸들러 (customId 접두사 라우팅)
  events/       게이트웨이 이벤트 + 인터랙션 라우터
  modules/      비즈니스 로직 (티켓·주문·패널·설정 뷰·로그)
  storage/      JsonStore(원자적 쓰기·직렬화 큐·손상 복구) + 도메인 스토어
  config/       env 검증, 상수(customId·색상·제한), 설정 스키마
  types/        도메인·핸들러 타입
  utils/        임베드 팩토리, 권한, 쿨다운, 포맷, 로거
data/           JSON 데이터 (자동 생성)
```

### 설계 원칙

- 모든 customId·색상·제한값은 `config/constants.ts` 단일 출처 (매직 스트링 금지)
- 설정 항목은 `config/settingsSchema.ts`에 선언만 추가하면 GUI·저장·표시에 자동 반영
- JSON 쓰기는 임시 파일 + rename으로 원자적, 스토어별 큐로 동시 쓰기 직렬화
- 버튼은 유저별 쿨다운(3초), 티켓/주문은 유저당 1건 중복 방지
